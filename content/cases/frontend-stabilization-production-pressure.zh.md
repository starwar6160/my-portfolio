## 结果摘要

- 数天内稳定 **74+ 项关键问题**，提交 **120+ 个原子化修复**
- 刷新后被强制登出等认证问题消除，WebSocket 连接恢复稳定
- Cypress 测试恢复可用，业务侧 QA 不再被阻塞
- 未做大规模重写，全部通过小步、可验证的修改完成

## 项目背景与约束

一个 Vue 3 / TypeScript 实时消息平台在前端负责人变更后进入生产紧急状态。平台包含实时消息、WebSocket 通信、认证授权、浏览器端业务流程和自动化 QA。积压的 P0/P1 问题正在阻塞测试、交付和客户验收。

约束：代码库庞大且为接手代码、熟悉时间有限、交付压力持续、多个 P0/P1 问题同时存在。修复必须避免引入新的回归。

## 原始问题

刷新后强制登出、WebSocket 不稳定、白屏、界面卡死、认证竞态、Cypress 不稳定、前后端契约不一致、Snowflake ID 精度风险。

多个故障相互叠加、症状相互掩盖，单点修复经常引出次生故障。

## 问题定位与根因分析

把前端当作生产事故而不是 UI 项目处理，依据生产日志、浏览器行为、网络时序、状态流转轨迹、认证流程和 Cypress 失败边界取证：

```text
复现 → 观察 → 确定故障边界 → 原子化修复 → 验证 → 重复
```

大部分问题来自**状态归属不清**：

- **认证状态**同时存在于路由守卫、刷新流程、内存状态和 token 生命周期逻辑中，刷新和重试时会出现分歧，导致会话丢失和强制登出。
- **WebSocket 连接归属**不确定：重复订阅、残留连接和互相竞争的重连逻辑，导致消息丢失和状态不一致。
- **前后端契约**发生漂移；64 位 Snowflake ID / Int64 值超出 JavaScript `Number` 的安全整数范围，存在精度丢失风险。

表面上是前端问题，本质上是分布式系统式的一致性问题。

## 技术方案与关键取舍

1. **认证状态单一归属**：统一认证状态的所有权，移除刷新触发登出的路径，消除 token 生命周期竞态。
2. **WebSocket 生命周期显式管理**：清理残留连接引用，重连行为确定化。
3. **运行时契约校验**：在 API 边界做 Schema 校验和载荷规范化，Snowflake ID 按字符串安全处理。
4. **测试基础设施恢复**：稳定 Cypress 执行路径，把已修复的故障转化为回归测试。
5. **交付策略**：小步原子提交，每次修改后做运行时验证，上线前验证失败路径，控制影响范围。

取舍：在交付压力下不做整体重写，而是逐个确定故障边界后做针对性的低风险修复。

## 适用场景与工程价值

适用于接手陌生的生产系统、多个故障叠加、需要在交付压力下快速恢复稳定的场景。“确定故障边界 → 明确状态归属 → 运行时验证 → 渐进修复”的方法同样适用于后端平台、云服务和分布式系统。
